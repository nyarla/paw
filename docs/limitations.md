# PAW audio wire 既知の制約

Status: Draft

このプロジェクトは、Wine の制約を理解しているユーザー向けの機能を含む。以下は「バグ」ではなく、設計上許容する制約である。

## Wine

- iLok / ドングル / カーネルドライバに依存するプラグインは動作しない可能性が高い
- COM / デスクトップ環境を要求するプラグインは、ヘッドレス環境で失敗する可能性がある
- GUI 前提のプラグインは、パラメータ proxy / GUI streaming 実装まで操作できない
- GPU アクセラレーションを前提とする GUI は、Wine の環境によって表示 / キャプチャに失敗する可能性がある
- 32-bit プラグインは MVP の対象外
- DAW のサンドボックス設定によっては、プラグインからの Host プロセス起動が制限される
- Wine prefix をまたぐプラグイン間 IPC は共有されない
- 同一 prefix 内でも、プラグインがプロセス内グローバルに依存する場合は同一 Worker が必要

## プロセスモデル

- 1 prefix に Supervisor 1 つ、ベンダーグループごとに Worker 1 つ
- 同一ベンダーのプラグインは同一 Worker に集約される
- 異なるベンダーは別 Worker に分離される
- 同一 Worker 内の 1 プラグインがクラッシュすると、その Worker の全セッションが失われる
- Worker のクラッシュ後、Client は state キャッシュからセッションを再作成する
- Supervisor がクラッシュした場合、Worker も終了する

## 音声 / レイテンシ

- ASIO バッファサイズそのものはプラグイン API から直接取得できない
  - CLAP の `max_frames_count`、VST3 の `maxSamplesPerBlock` を代理値として使う
- DAW の ASIO バッファをプラグイン遅延に加算しない（PDC の二重補正を避ける）
- ネットワークジッターが設定値を超えるとアンダーラン / 無音になる
- オフラインレンダリングは MVP 非対応
- プラグインが固定ブロックサイズを要求する場合、MVP では制約が出る可能性がある

## プラグイン形式

- MVP は CLAP のみ
- VST3 / VST2 は後続フェーズ
- VST3 SDK のライセンス（GPLv3 または Steinberg ライセンス）を確認する必要がある
- VST2 SDK は配布条件に注意が必要。clean-room header などの選択肢を検討する
- macOS / AU は開発用ハードウェアが無いため現時点の対象外

## ライセンス / 法務

- 商用プラグインのバイナリ転送や共有は EULA 違反になり得る
- 本プロジェクトは「各自の環境にあるプラグインを Host がロードする」構成とし、バイナリ配布機能は持たない
- Windows プラグインを Wine で動かすこと自体のライセンス条件は、各プラグインの EULA を確認する
